# 播放队列

队列采用独立条目标识，歌曲本身的来源与身份保持原有规则。面板集中展示实际队列与操作。

## 操作规则

| 操作 | 行为 |
| --- | --- |
| 打开队列 | 定位当前项；显示总数、当前序号和播放模式 |
| 点击封面、双击行、行聚焦后 Enter / Space | 当前项暂停或恢复，其他项切换播放；恢复当前项保留进度 |
| 拖动 | 插到目标歌曲前，拖至列表底部空白区域移到末尾；保留当前歌曲、进度与暂停状态 |
| 上移 / 下移 | 更多菜单和右键菜单均可操作，提供拖动以外的排序入口 |
| 下一首播放 | 优先复用队列中已有的非当前歌曲；最近一次指定排在最前，在随机和单曲循环中也优先执行；不打断当前播放 |
| 移出其他歌曲 | 保持当前音频与进度；同步调整游标、随机访问历史及预取 |
| 移出当前歌曲 | 优先选手动指定的下一首，否则选下一行，末项移除后选第一行；播放或加载中继续，暂停中保持暂停 |
| 清空 | 停止、取消加载、清理当前歌曲与进度；同时清理歌词及封面固定状态 |
| 直接播放本地歌曲 | 选中队列中的同一歌曲，或追加后播放，播放栏与队列使用同一选择 |
| 重启 | 恢复为暂停；保留队列、进度、随机历史和手动指定的下一首顺序 |

单曲循环的自然结束仍重播本曲，手动按“下一首”则前进。完整列表中显式存在的重复歌曲继续保留，每个副本独立操作。

## 实现

- `internal/player/queue.go` 集中实现替换、清空、选择、移除、移动和下一首安排。UI 命令传递条目 ID；被移除或被替换的旧条目操作直接忽略，排序后不依赖旧序号。
- `QueueSnapshot` 在同一读锁内读取版本、游标、模式、状态和下一首；版本变化时才复制歌曲，UI 保留没有变化的列表快照。
- `QueueDrawerState` 只保存开关、列表和只读快照；关闭或清空时释放旧列表引用。64 高曲目行、44 封面和 32 操作区域沿用现有主题规格。
- 虚拟列表按条目 ID 保持状态。拖放使用 MyGo 原生的值拖放，把条目 ID 带到目标行；边缘滚动由 MyGo 处理。无需把跨帧序号重新解释为另一首歌曲。
- 歌词页过渡时的背景播放栏不打开队列面板，避免复制正在使用的列表状态。
- 会话仍存储原歌曲数组和序号，新增可选 `nextIndices`。旧配置可继续读取，损坏的可选字段独立忽略；恢复时丢弃越界、重复和指向当前项的下一首索引。
- 所有解码器、流和设备的关闭继续放在后台，持锁时只分离旧资源并更新内存状态。

## 修改时的关注点

核查空队列、当前项与其他项移除、前后移动、相同歌曲的多个副本、无效旧条目命令、下一首优先级、随机历史重映射、快照复制以及旧配置兼容。验证方式遵守[贡献说明](../CONTRIBUTING.md)，构建结果不能替代实际窗口、拖动、键盘交互与播放行为的验证。
